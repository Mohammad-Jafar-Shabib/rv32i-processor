RV32I Instruction Set Architecture Specification

Computer Architecture & Organization (401331) · Phase 1 Deliverable · Team RISC-V · Fall 2026/2027 · v1.0 · November 11, 2026

1. Overview

The processor implements the RV32I base integer instruction set: 32-bit fixed-width instructions, 32 general-purpose registers, byte-addressable little-endian memory. All loads require natural alignment (lw: 4-byte, lh: 2-byte); misaligned access is a programming error and traps in simulation. The M extension is not implemented; multiplication is synthesized in software (shift-and-add), which the Phase 4 benchmarks exercise deliberately.

2. Register File Specification

32 registers × 32 bits. Dual-read, single-write ports; writes are committed on the rising clock edge and are inhibited when the destination is x0 (x0 is hardwired to zero).

3. Instruction Formats

Every instruction is 32 bits wide. Bit 31 is the MSB; opcode occupies bits [6:0]. Six formats cover the entire set.

5. Implementation Subset Priorities

PhaseInstruction coverage
Phase 2Core arithmetic/logic/shift (ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU + immediate forms), LW, SW, BEQ, BNE, JAL — enough for first correct programs vs. RARS.
Phase 3Full RV32I table above running in the 5-stage pipeline with forwarding and hazard stalls; direct-mapped cache in the load/store path.
Phase 4Full subset under benchmark load (sort, Fibonacci, matrix mul); ECALL/EBREAK terminate simulation and emit results for the RARS differential check.

6. Memory Model

Byte-addressable, little-endian, unified address space with separate instruction and data RAM interfaces in Phase 2 (simplified fetch path) merged behind the Phase 3 cache. RV32I loads/stores use natural alignment; RARS assembles data sections with automatic alignment, and the benchmark suite contains no misaligned accesses.

7. ALU Functional Specification

The ALU is shared by the EX stage of every format class. A 4-bit control word selects the operation; Zero and Overflow/Sign flags are produced every cycle. SLT/SLTU/branches derive their result from the subtract path, so no separate comparator is needed.
