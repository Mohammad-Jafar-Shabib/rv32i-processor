A 32-bit RISC-V Processor for Embedded Benchmark Workloads

Computer Architecture & Organization (401331) · Phase 1 Architectural Proposal · Fall 2026/2027 · Team RISC-V · November 11, 2026

1. Problem Statement

Cost-sensitive embedded systems need a small, deterministic, general-purpose core whose behavior can be fully understood from gate level to software. RISC-V is an open, royalty-free ISA that makes such a core feasible as a course-scale project. Our objective is to design, implement in Verilog, and verify a 32-bit RISC-V (RV32I base subset) processor that, by Phase 4, executes complete assembly benchmark programs (sorting, Fibonacci, matrix multiplication) and is characterized by measured CPI, execution time, clock frequency, and cache miss rate, documented in an IEEE-style report and defended orally in Week 14. The dominant risk is under-scoping; therefore the architecture is fixed now and later phases only extend a working design.

2. Objectives

  • Specify a complete RV32I subset: instruction encodings, opcode map, and register file (Phase 1, this deliverable).
  • Build a correct single-cycle datapath — ALU, register file, control unit, instruction/data RAM — verified by self-checking testbenches (Phase 2).
  • Extend to a five-stage pipeline with hazard detection and forwarding, plus a direct-mapped cache with hit/miss logic (Phase 3).
  • Execute the benchmark suite end-to-end and produce quantitative performance analysis (Phase 4).
  • Maintain a public GitHub repository with continuous version history and a 3–5 minute demo video (all phases).

3. Scope

In scopeOut of scope
RV32I integer subset (~40 instructions) exactly as specified in the accompanying ISA Specification; 32×32-bit register file, x0 hardwired to zero; byte-addressable little-endian memory. Standard extensions M/F/A/D/C (multiplication is synthesized in software by shift-and-add, which the benchmarks exercise explicitly).
Single-cycle baseline in Phase 2 evolving into a 5-stage pipeline (IF–ID–EX–MEM–WB) in Phase 3, with full data forwarding, load-use stall, and predict-not-taken branch policy. CSRs, interrupts/exceptions, MMU and virtual memory, multi-core, superscalar or out-of-order techniques.
Phase 3 memory hierarchy: unified memory fronted by a 1 KiB direct-mapped cache (32 lines × 32 B blocks), hit/miss logic, miss-penalty modeling in simulation. FPGA synthesis and physical implementation; set-associative caches (kept as documented trade-off alternatives).

6. Toolchain & Verification Strategy

HDL/simulation: Verilog (IEEE 1364-2005) simulated with Icarus Verilog (iverilog/vvp), waveforms via GTKWave when needed. Golden reference: RARS (RISC-V Assembler and Runtime Simulator) runs every test program; processor simulation output must match RARS output exactly. Version control: Git/GitHub with one commit minimum per work item. Verification approach: every module gets a self-checking testbench asserting expected outputs (already established in Phase 1 — see sim/tb_phase1.v), escalating to full-program differential testing against RARS from Phase 2 onward.

7. Expected Results

A working RV32I processor executing the full benchmark suite with correctness proven by differential testing; measured CPI ≤ 1.2 for the pipelined configuration; cache hit/miss ratios reported per benchmark; a clean 6–8 page IEEE report and a reproducible public repository. This positions the team for full marks on Processor Implementation (up to 7/20) and Documentation (up to 9/20) criteria.
